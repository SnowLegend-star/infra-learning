# 传统文件传输发展历程

## 单机文件传输

首先，我们来讨论单机文件传输的几种方式。

### 1. 传统方式（`read()` + `send()`）

数据流动过程如下：

```scss
磁盘 (disk)
   ↓  [DMA：设备→内核页缓存 page cache]
内核页缓存 (kernel page cache)
   ↓  [CPU memcpy：copy_to_user]
用户缓冲区 (user buffer)
   ↓  [CPU memcpy：copy_from_user]
socket 缓冲区 (kernel socket buffer)
   ↓  [DMA：网卡读内存]
网卡 (NIC)
```

➡️ 这过程中：

- 有 **4 次数据移动**
  - 两次 DMA（disk→pagecache，socket→NIC）
  - 两次 CPU 拷贝（pagecache→user，user→socket）
- 有两次用户态↔内核态切换（`read()` / `send()`）

------

### 2. 使用 `sendfile()` 的方式

`sendfile()` 直接让内核在**文件页缓存和 socket 缓冲之间传输数据**，**跳过用户空间**：

```scss
磁盘 (disk)
   ↓  [DMA：设备→内核页缓存 page cache]
内核页缓存 (kernel page cache)
   ↓  [内核内部引用 / DMA 传输]
socket 缓冲区 (kernel socket buffer)
   ↓  [DMA：网卡读内存]
网卡 (NIC)
```

➡️ 结果：

- 没有用户空间拷贝（**减少两次 CPU memcpy**）
- 用户态只调用一次 `sendfile()`（**少一次系统调用切换**）
- 内核可以直接把文件页缓存的页（page）映射为 socket 发送缓冲的片段（page fragment / scatter-gather list）



## ✨ 3.进一步优化：`splice()` 与 `MSG_ZEROCOPY`

| API            | 优势                           | 场景                 |
| -------------- | ------------------------------ | -------------------- |
| `sendfile()`   | 文件 → socket，最经典          | 静态文件发送         |
| `splice()`     | 任意 fd → fd，可结合管道零拷贝 | 比如文件→管道→socket |
| `MSG_ZEROCOPY` | 发送大块数据时异步零拷贝       | 高性能 socket 应用   |

## 4. Scatter-Gather DMA（SG-DMA）

**4.1** **基本定义**

传统 DMA（Direct Memory Access）一次只能**从一段连续的物理内存**中读取数据。
 而 **Scatter-Gather DMA** 允许一次传输中，**数据分布在多个非连续的内存页（scatter）**，由驱动程序提供一个**描述符列表（gather list）**告诉网卡（或存储控制器）如何拼接发送。

**4.2** **举个例子**

假设 TCP 要发送一个大文件，而这个文件在内核中对应了多个不连续的页：

| 页    | 物理地址 | 长度 |
| ----- | -------- | ---- |
| page0 | 0x10000  | 4096 |
| page1 | 0x28000  | 4096 |
| page2 | 0x3A000  | 4096 |

在没有 SG-DMA 时：

- 驱动必须先把这些页“拼成”一块连续的内存，然后再告诉网卡 DMA。
- 这就需要一次 **CPU 拷贝**。

而有了 SG-DMA：

- 驱动只要把这些页的信息（地址 + 长度）写到一个**scatter-gather 列表（SG list）**。
- 网卡 DMA 引擎会自动从这些离散的内存块中 **分段读取并顺序拼接发送**。
- 不再需要额外的 CPU 拷贝。



具体来说：

传统 DMA 工作时，需要驱动程序提供一个**连续的物理内存起始地址**和**总长度**。DMA 控制器会从这个起始地址开始，连续地读取或写入数据（按地址递增顺序），直到完成总长度的数据传输。它无法 “跳着” 访问不连续的物理地址（比如从 0x10000 读取 4096 字节后，自动跳到 0x28000 继续读取）。

而问题中，文件的数据分散在多个不连续的物理页中（0x10000、0x28000、0x3A000）。此时，网卡的 DMA 控制器（不支持 SG）无法直接读取这些分散的页 —— 因为它没有 “分散 - 聚集” 能力，不知道这些页的地址和长度，也无法自主切换到下一个不连续的页。

因此，驱动程序必须先通过 CPU 执行一次拷贝：把这些分散在不同物理页中的数据，逐一读取出来，再依次写入到一块**连续的物理内存**中（比如专门分配一块连续的缓冲区）。这样一来，DMA 控制器就可以通过这个连续的起始地址和总长度，完成数据传输了。

具体过程可以拆解为：

1. 驱动程序先向内核申请一块**连续的物理内存缓冲区**（比如通过 `kmalloc` 等接口，确保其物理地址连续）。
2. CPU 依次访问每个分散的物理页（page0、page1、page2），将其中的数据逐个读取到寄存器中，再写入到上述连续缓冲区的对应位置（比如 page0 的数据写到缓冲区起始地址，page1 的数据写到缓冲区 +4096 位置，以此类推）。
3. 当所有分散的数据都被拷贝到连续缓冲区后，驱动程序将这块连续缓冲区的物理地址和总长度告诉网卡的 DMA 控制器，由 DMA 直接从这块连续内存中读取数据并发送。

整个过程中，数据的 “搬运” 和 “拼接” 动作是由 CPU 执行的（通过加载 / 存储指令），最终结果是**在内存中形成了一块连续的数据块**，以满足传统 DMA 对连续物理地址的要求。

总结来说：传统 DMA 对 “连续物理内存” 的依赖，与实际数据 “分散存储” 的矛盾，必须通过 CPU 拷贝来消除 —— 用 CPU 把分散的数据 “拼接” 成连续块，才能满足 DMA 的工作要求。

------

**4.3 在 Linux 网络栈中的作用**

在 Linux 网络栈（特别是 `sendfile()` 或零拷贝发送）中，SG-DMA 非常关键。它让网卡能够直接“读”散落在内核页缓存中的数据，而不用重新复制成连续缓冲。

当你用 `sendfile()` 发送文件时：

- 内核把文件页（page cache）直接挂到 socket 的 skb 结构中（`skb_shinfo(skb)->frags[]`）。
- 如果网卡支持 SG-DMA，那么驱动会把这些页的物理地址构造成 scatter-gather list。
- **网卡硬件** 再直接 DMA 读出这些页并发送。

🟢 这样就实现了真正的零拷贝（zero-copy）：

- CPU 不需要搬数据；
- 内核页缓存的页直接被网卡读走。
